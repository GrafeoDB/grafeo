# Upgrading to 0.6

0.6 is a breaking release: it changes the database file format and a number of APIs and query results. This page
lists what to do, grouped by where it affects you. The [CHANGELOG](../changelog.md) has every entry, including the
fixes that change results.

## Before You Upgrade

1. **Pin the new minor version**: `grafeo = "0.6"` in Cargo, `"@grafeo-db/js": "^0.6.0"` in npm, `grafeo~=0.6.0`
   for pip and uv (see [Versioning](../versioning.md#pinning-a-version)).
2. **Stop every 0.5.x process** that uses a database before 0.6 opens it. 0.5.x cannot open a migrated database.
3. **Plan for the migration**: the first read-write open of a 0.5.x database migrates it to the 0.6 format and keeps
   the old files under `.pre-0.6` names, which are your way back. The migration needs free disk space for a copy of
   the database. Read-only opens read a 0.5.x database without changing it. See
   [Upgrading from 0.5](../user-guide/persistence/persistent.md#upgrading-from-05) for the details, encrypted
   databases and builds without the `wal` feature.
4. **Open every 0.5.x database for writing once with 0.6**: 0.7 will no longer read 0.5.x databases.

## Database Files

- **Every database is a single file**, whatever its extension, with its write-ahead log in `<path>.wal/` while it is
  open. A 0.5.x WAL directory is migrated to a file at the same path.
- **Opening a directory that is not a 0.5.x database fails**, an empty one included. Use a path where nothing exists
  yet, such as a file inside that directory.
- **`save()` fails if the path exists**: save to a new path, or remove the old file first.
- **A damaged write-ahead log stops the open** with an error that names the file and offset; 0.5.x skipped the
  damage and went on. To open such a database anyway, replay the commits before the damage with
  `Config::with_wal_salvage()` (Python `wal_salvage=True`, Node.js `walSalvage`); the rest of the log is kept in
  `<path>.wal.damaged`.
- **Backup manifests and cursors are JSON**. 0.6 restores 0.5.x backups and continues their chains, but 0.5.x cannot
  read a backup directory that 0.6 has written to.

## Query Results

These changes apply in every binding.

- **A number with a point is an exact decimal** in GQL and SQL/PGQ: `0.1 + 0.2 = 0.3` holds, and `1.50` keeps its
  two digits. Write `1.5e0` or `1.5F` for a float. In SPARQL, `1.5` and `xsd:decimal` literals are decimals, and an
  integer divided by an integer is a decimal (`5 / 2` is `2.5`, it was `2`). Bindings return decimals as
  `decimal.Decimal` (Python) or `{"$decimal": "1.50"}` (Node.js, WebAssembly, C).
- **Overflow and division by zero fail the query** with `GRAFEO-Q006` (GQLSTATUS `22003` or `22012`) in GQL,
  Cypher and SQL/PGQ; they returned null. Guard a division with a condition (`WHERE x <> 0 AND 10 / x > 1`) if
  zero can occur.
- **GQL sorts nulls last** in both directions; `ORDER BY x DESC` put them first. Write `NULLS FIRST` to keep the old
  order. Cypher keeps openCypher's order.
- **A `WHERE` or `FILTER` right after `INSERT`, `CREATE`, `MERGE` or `DELETE` is an error** in GQL: put the
  condition before the write (`MATCH (n) WHERE n.age > 30 DETACH DELETE n`).
- **A statement nests at most 64 levels deep and its plan at most 128**; a deeper statement fails before it runs.
  Property values nest at most 128 levels deep, and the migration names any value that is deeper.
- **Type DDL refuses property types Grafeo does not support** (`INT32`, a typo such as `STIRNG`), naming the
  supported ones; they declared a property of type `ANY`.
- **The Arrow export keeps lists, maps and durations typed** (Python `to_arrow()` and the polars and pandas
  conversions, Node.js `toArrowIpc()`): they were text.
- Several algorithm results are corrected, among them k-core (core numbers) and Louvain (merges level by level).
  See *Result changes* in the CHANGELOG.

## Rust

- **The minimum Rust version is 1.99.0.**
- **Build `Config` with its constructors and methods**: it is `#[non_exhaustive]`, so a struct literal no longer
  compiles. Its public fields are deprecated: read a setting with its getter.

  ```rust
  // 0.5
  let config = Config { path: Some("data.grafeo".into()), wal_enabled: false, ..Config::default() };
  // 0.6
  let config = Config::persistent("data.grafeo").without_wal();
  ```

- **Option and result types are `#[non_exhaustive]`**: build `EncryptionConfig` with `EncryptionConfig::new`,
  `CdcRetentionConfig` with `CdcRetentionConfig::unlimited()` and its `with_*` methods, `EdgeUpsertOptions` with
  `EdgeUpsertOptions::new()`, and `DurabilityMode::batch(..)` or `DurabilityMode::adaptive(..)`. Match a result type
  or a `Batch` or `Adaptive` mode with `..`.
- **More calls return `Result`**: `drop_graph`, `create_property_index`, `drop_property_index`,
  `drop_vector_index`, `drop_text_index`, `batch_insert_rdf` and `create_projection`. Add `?`.
- **`text_search` and `hybrid_search` take a `filters` argument**: pass `None` to search as before.
- **`compact()` returns a `CompactReport`**. The compacted store's API is gone: `layered_store()`,
  `compact_tiered()` and `grafeo::database::compact_tiered`, as `compact()` no longer builds a separate store.
- **A damaged file is `Error::Corruption`** (`Corruption { what, file, offset }`).
- **`store()` returns `Arc<RowGroupStore>`** (`grafeo_core::graph::rowgroup`), the store the database now holds its
  graphs in: `LpgStore` is gone. Write through sessions or the direct API: a write through the store's own methods
  is not logged and not undone by a rollback. `wal()` returns the new WAL writer.
- **Removed**: `Config::wal_flush_interval_ms` (set the flush with `with_wal_durability`) and
  `GrafeoDB::adaptive_config()`.
- **A store passed to `with_store`**: the transactional writes and property removals of `GraphStoreMut` return
  `Result` (wrap the old results in `Ok(...)`), and `GraphStore::try_get_node_property_batch` is new.

## Bindings

- **Python**: `db.algorithms.kcore()` returns `{"core_numbers": {...}, "max_core": n}`, like `louvain()`.
  `compact()` returns a dict.
- **Node.js and WebAssembly**: `compact()` returns an object.
- **Go**: `DropVectorIndex` returns `(bool, error)`, like `DropPropertyIndex`.
- **C**: `grafeo_drop_property_index`, `grafeo_drop_vector_index`, `grafeo_create_projection` and
  `grafeo_drop_projection` return -1 on an error.
- **Metrics**: the Block-STM metrics are removed, also the `grafeo_block_stm_*` counters on grafeo-server's
  `/metrics`; they always read 0.

## Deprecated in 0.6, Removed in 0.7

Each of these still works in 0.6 and warns where your compiler or tooling can. Move to the replacement before you
upgrade to 0.7.

| Deprecated | Use instead |
| --- | --- |
| The public fields of `Config` | its getters, and its constructors and `with_*` methods |
| `Session::set_auto_commit`, `Session::auto_commit` | `begin_transaction` to group writes; a write outside a transaction always commits on its own |
| `Config::adaptive`, `with_adaptive`, `without_adaptive`, `AdaptiveConfig` | nothing: adaptive execution was never wired in |
| `StorageFormat::SingleFile`, `StorageFormat::WalDirectory` | `StorageFormat::Auto`, the default: every database is a single file |
| C `grafeo_open_single_file`, Go `OpenSingleFile`, Dart `GrafeoDB.openSingleFile` | `grafeo_open`, `Open`, `GrafeoDB.open` |
| `recompact()` | `compact()` |
| `BackupCursor::log_sequence` | `wal_lsn` |
| The `compact-store` feature | nothing: every build that opens files reads a database compacted by 0.5.x |
